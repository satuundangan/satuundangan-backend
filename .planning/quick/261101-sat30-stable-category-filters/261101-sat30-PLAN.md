# SAT-30: Stable category search links

## Goal
Renaming a category does not invalidate admin links or filters that point to that category.

## Scope
- Use immutable category IDs for admin drilldown links and category filter selections.
- Retain prior normalized category names as aliases when renamed, so existing name-based links still resolve.
- Make backend admin template and invitation filters accept IDs and aliases, while retaining compatibility with existing name-based links.
- Normalize category names on create/rename and reject duplicate names regardless of whitespace or case.
- Preserve the existing category entity relationship used in the public catalog.

## Constraints
- Target `development` only; no production deploy or production data access.
- Do not invent new filter taxonomy semantics; `filterGroup`/tags remain separate metadata.
- No tests requested; validate builds and inspect the diff.

## Verification
- Backend `npm run build`.
- Frontend `CI=1 npm run build`.
- `git diff --check` in both repositories.
