# SAT-29: Snapshot template attribution at checkout

## Goal
Paid and free invitation transactions remain attributed to the template selected when checkout starts, even if the invitation template changes later.

## Scope
- Add nullable `templateDesignIdSnapshot` to `Payment`; existing rows remain readable under TypeORM `synchronize`.
- Populate the snapshot when creating paid and free invitation payments.
- Group paid/free template metrics by the stored snapshot, with a fallback to the invitation's current template for legacy payments.
- State the legacy fallback in metric definitions.

## Constraints
- Development branch only; no production deploy or production data access.
- Do not alter payment settlement behavior.
- No tests requested; validate compilation and inspect the final diff.

## Verification
- `npm run build` in the backend.
- `git diff --check`.
- Review payment creation and metrics query changes.
