# SAT-27: Record first publication time

## Goal

Admin customer timelines can show when an invitation was first published, using a timestamp recorded at the publication transition.

## Scope

- Add a nullable `publishedAt` timestamp to invitations; old rows remain unknown.
- Set it when publication first changes from false to true through owner update, free activation, verified payment settlement, payment reconciliation, or dev simulation.
- Include the timestamp in admin customer detail and emit one timeline event per published invitation, clearly marking legacy timestamps as unknown.
- Show the publication time or an explicit unknown state in the user detail panel.
- Preserve the existing wedding completion state as unknown because no completion event is stored.

## Constraints

- Target `development` only; do not deploy or read production data.
- Rely on the repository's TypeORM `synchronize: true`; do not add migrations.
- Keep legacy publication timestamps null; do not backfill from `updatedAt` or payment settlement.
- No tests requested; validate builds and `git diff --check`.

## Verification

- Backend `npm run build`.
- Frontend `CI=1 npm run build`.
- `git diff --check` in both repositories.
